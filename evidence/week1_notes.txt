Week 1 – Foundations of GRC as Code

Summary
Built the initial GRC-as-Code lab environment using Terraform, OPA, Checkov, YAML control definitions, and evidence capture.

Activities completed
1. Created the repository structure for terraform, policies, controls, and evidence.
2. Built an insecure S3 Terraform example for control-testing purposes.
3. Created an OPA policy to prohibit public S3 buckets.
4. Created a second OPA policy to require S3 versioning.
5. Ran Checkov scans against the Terraform examples.
6. Created a baseline S3 control family in YAML.
7. Created an initial cloud control taxonomy.
8. Added a secure S3 example for comparison.

Key observations
1. A single insecure S3 resource can violate multiple controls at once.
2. Control enforcement can come from both policy engines and infrastructure scanning.
3. Secure configuration reduces findings but does not automatically eliminate all risk.
4. Governance controls should be separated from enforcement tools.
5. Cloud governance is better represented as continuous assurance than point-in-time audit activity.

Outcome
Week 1 established the foundations of the lab:
- Infrastructure as Code
- Policy as Code
- Compliance scanning
- Control definition
- Evidence capture
